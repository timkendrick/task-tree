Currently, `tt task checkpoint` creates a checkpoint commit with whatever changes are currently in the working copy, and appends the checkpoint commit to the current branch tip.

This is the only tt operation to result in non-metadata commit contents, which feels like inconsistent design.

Let's move to a 'metadata-plane vs data-plane' model, enabling a clean separation whereby all autogenerated `tt` commits contain only metadata (`.tt/…` file) contents, and all user commits contain only data (project file) contents.

Let's change the checkpoint behavior such that instead of appending a linear commit, it creates a new merge commit whose parents are the task bookmark commit and the current head commit, effectively accumulating all intermediate commits into a 'side-chain' branch.

Like other commands, the `tt task checkpoint` command should now enforce that the working copy is clean before executing the command.

This will obviate the need for the checkpoint command's `--squash` argument, which should be removed entirely, and all references to it expunged from the code base and all markdown documentation.

This is a fairly fundamental change, so it may require far-reaching changes to the documentation beyond DESIGN.md. Make sure to read all markdown files within the codebase to determine if any other documentation needs updating.
